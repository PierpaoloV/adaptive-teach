# Milestone protocol

Use this protocol when every planned lesson in the current milestone is `done`
and the milestone itself is `not_done`.

## Completion criterion

A milestone is complete when a cumulative assessment shows every load-bearing
capability at `operational` or higher, unmet capabilities have passed targeted
reassessment, one verified PDF exists for every module, estimates are
recalibrated, and the next milestone is detailed from current evidence or the
mission is complete.

## 1. Assess cumulatively

Use questions and tasks not rehearsed in the lesson sequence. Include delayed
retrieval, teach-back, at least one novel problem, independent application, a
transfer case or counterexample, and an assistance record.

Keep assessment separate from guided practice. Prefer external exercises,
public problem sets, test suites, or other independent sources where available.

## 2. Remediate only the gap

If a load-bearing capability is below `operational`, create a targeted recovery
lesson and reassess that capability. Do not repeat the entire module. Preserve
both the failed evidence and the new evidence in `LEARNER.md`.

## 3. Compile modules

Compile each module from its canonical lesson Markdown sources. Render and
verify one module PDF using `pdf-protocol.md`. Do not edit the derived PDF.

## 4. Replan

Compare predicted and actual effort, assistance, retention, and scope. Update
the remaining workload range and confidence. Keep future milestones high-level;
detail only the next milestone, capped at three months, from the current learner
model.

Validate all artifacts. Mark the milestone `done` as the final operation. Mark
the mission `done` only when its observable success evidence is present.
