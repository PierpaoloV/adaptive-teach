# Onboarding protocol

Use this protocol only while `ONBOARDING.md` is `not_done`.

## Completion criterion

Onboarding is complete when the observable mission, time constraints, source-
grounded prerequisite map, diagnostic transcript, initial learner model, and
first detailed milestone all exist, and every initial placement is tied to
evidence or marked uncertain.

## 1. Define the mission

Ask one question at a time until the following are concrete:

- intended use;
- observable result;
- success evidence;
- out of scope;
- deadline or `none`;
- weekly time budget;
- preferred session duration.

Transform broad topics into capabilities. Preserve the user's wording in
`ONBOARDING.md`, then record the agreed observable mission.

## 2. Research and map the destination

Read `source-policy.md` and the relevant domain guide. Gather enough trusted
material to identify outcomes, prerequisite relationships, representative
practice, and plausible workload. Create a provisional high-level map before
asking diagnostic questions. Mark inferred edges and disagreements between
sources.

## 3. Run the diagnostic assessment

Ask 10-15 primary questions, one at a time. Follow up when an answer could be
guessing, internally inconsistent, or based on a different mental model.

Choose questions that can change the starting point, terminology, examples,
scaffolding, or roadmap. Mix explanation with prediction and application. Count
a practical task as one primary question. Encourage `I don't know` as useful
evidence.

After every answer, append the question, answer, follow-up, and provisional
interpretation to `ONBOARDING.md`. Keep onboarding `not_done` until the full
diagnostic record is saved.

## 4. Create initial state and roadmap

Build `LEARNER.md` using `learner-model.md`. Write a high-level roadmap to the
full destination, then detail only the first milestone. A milestone lasts at
most three months. Later milestones contain outcomes and exit criteria, not
prewritten lessons.

Estimate workload as an optimistic-probable-pessimistic range. State sources,
assumptions, exclusions, and confidence. If the desired deadline is implausible,
preserve the destination and negotiate a realistic first milestone.

Validate the workspace, then change onboarding to `status: done` as the final
operation.
